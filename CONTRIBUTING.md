# Contributing

Thank you for helping improve defensive cybersecurity and secure software engineering.

## Before contributing

- Read [SECURITY.md](SECURITY.md) and [the research scope](docs/SCOPE_AND_AUTHORIZATION.md).
- Use **public issues only for non-sensitive feature ideas, documentation improvements, and sanitized bug reports**.
- Share suspected vulnerabilities using a private channel, not public issues or pull requests.
- Do not test third-party assets without explicit written permission and an agreed scope.
- Do not upload secrets, tokens, personal information, private CI logs, or actual attack payloads targeting live systems.

## Contribution quality

For research claims, distinguish **hypothesis**, **reproduced observation**, **validated fix**, and **independent verification**. Include enough method and environment information to permit authorized reproduction. Prefer local fixtures and synthetic data.

For code submissions (after a license is approved): explain the defensive intent, describe potential misuse, provide tests and safe defaults, and keep permissions minimal.

## Pull request checklist

- [ ] Authorized scope documented
- [ ] No secrets or personal data
- [ ] Safety and abuse risks considered
- [ ] Tests or review steps included
- [ ] Results represented accurately
- [ ] No sensitive unpatched details publicly disclosed

## Licensing

An open-source license is **not yet selected**. Do not submit reusable source code intended for redistribution until project ownership and licensing terms are clarified.
